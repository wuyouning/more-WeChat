匹配普通启动预览策略的构建指纹：

```text
Weixin.exe SHA256
a832fb321ddb5f9701dd3a7bb1958804f09b620b9ad328f52e2e352651ab886c
4.1.15.13/Weixin.dll SHA256
10f8e995453e2da46d4f2b5080cd6da1f13cc5147746adc119ceae38cb039de5
```

EXE 的 Authenticode 检查为 Valid，签名主体为 Tencent Technology (Shenzhen) Company Limited。REA 静态检查该入口 EXE 未找到 Mutex 字符串（Evidence `ev_f1e658654f34f3f40851a21f98fdb7a535bee4d7197abd1b2ca93f2ab12a7f77`）；这只说明有界静态查询的结果，不证明没有单实例约束。真实互斥锁探针观察到 XWEB、插件、语音和用户身份等多种锁，不能把它们直接等同于应用启动锁。

内置 Windows 策略按版本号、EXE 和业务 DLL 的 SHA256 同时匹配。当前只有上述构建的 `normal` 启动策略；显示已验证还必须匹配验收记录的系统版本 `11 (22631)` 和架构 `x86_64`。其他/未知系统组合仍为未验证。`mutex` 引擎保留，但只有贡献者完成准确名称的真实验证后才可加规则；禁止用模糊名称匹配、跨用户/跨会话操作或结束微信代替。进程列表、复制句柄、重新核对对象身份及关闭之间仍存在 Windows API 无法完全消除的时序间隔，规则验证必须包括已有账号持续使用。

## 扩大验证范围与正式发布前的验收

当前已验证项仅覆盖上表明确通过的能力；截图、通话等未确认项目保留待验。新增平台、架构或微信构建时分别记录系统版本、来源、文件哈希、启动方式和日期；正式发布前继续完成以下检查，不能从双账号消息正常推定其他项目通过：

1. 原版未运行时启动至 2；确认是两个独立窗口，再分别登录两个测试账号。
2. 保持原版账号在线，启动第二个；两个账号分别发送测试消息、接收消息，截图和通话正常，原账号不被退出或覆盖。
3. 原本已有 2 个时再次点击目标 2，不新增；连续点击不能重入；设置小于当前数量不关闭任何实例。
4. 未安装、中文及空格路径、权限不足、启动后立即退出和部分成功都有正确反馈，不误报登录成功。
5. Mac：原版更新后提示旧副本，仅刷新停止的副本；刷新失败保留旧副本；原版和副本原有数据可用。运行中的副本及辅助进程不被替换。
6. 导出诊断为有效 JSON，用户名已隐藏，无聊天内容；关闭启动器不会关闭微信。

开发诊断命令（均不自动登录）：

```sh
# 只读：安装、主进程、兼容状态；Windows 额外观察本用户会话的互斥锁名称
cargo run --manifest-path src-tauri/Cargo.toml --example probe
# 显式执行一次普通启动；Windows 上不操作远程句柄
cargo run --manifest-path src-tauri/Cargo.toml --example normal_start_check -- --launch
# 使用正式编排，只有匹配策略的构建允许多开；现有数量达标时不新增
cargo run --manifest-path src-tauri/Cargo.toml --example launch_check -- 2
```

探针的终端输出可能包含本机路径、PID 和对象名称，分享前需自行脱敏。应用内“导出诊断”不会包含互斥锁名称、进程参数或聊天数据。
